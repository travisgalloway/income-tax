# Interface: curated snapshots (`src/data/debt_maturity.json`, `debt_holders.json` and siblings)

The consumer contract for the five outputs built from `pipeline/curated/snapshots.yaml`. Four are
**never auto-fetched** and carry `_meta.refresh.mode: "curated"` — `debt_maturity`,
`income_tax_by_group`, `oecd`, `cbo_effective_rates`, generated by
`pipeline/monthly/curated_snapshots.py`. The fifth, `debt_holders`, is **`"mixed"`** since #54:
its foreign holdings are fetched from a Treasury release and the rest of it is curated, so it has
its own builder, `pipeline/monthly/debt_holders.py`. Read this before charting from any of them;
the failure modes below are silent otherwise.

## The `refresh.mode: curated` shape

```json
"_meta": {
  "refresh": { "mode": "curated", "reason": "source publishes as a document, not a machine-readable feed" }
}
```

`Meta.refresh` (`src/data/types.ts`) reaches this field through a narrowed optional property, not
a cast through the index signature. Its `mode` is the union `'curated' | 'mixed'`, so a third mode
is a type error at every consumer rather than a string nobody checked.

## The `refresh.mode: mixed` shape — `debt_holders`

```json
"_meta": {
  "refresh": { "mode": "mixed", "reason": "foreign holdings fetched from Treasury International Capital … the public versus intragovernmental split, the total and the foreign share history are curated from Debt to the Penny and carry their own as_of" },
  "provenance": { "generator": "monthly/debt_holders.py", "vintage": "2025-11", "retrieved_at": "…" },
  "tic_grand_total_b": 9349.6
}
```

**Two dates, and both must be rendered.** `data.as_of` (`2026-08-07`) is Debt to the Penny's, for
the split and the total. `data.tic_as_of` (`2025-11`) is the Treasury International Capital release
month, for `top_foreign` only, and it equals `_meta.provenance.vintage`. Presenting one date as if
it covered both is the failure this shape exists to prevent.

**The TIC release month is PINNED, not discovered as "the newest".** The pin lives in
`pipeline/curated/snapshots.yaml` as `debt_holders.tic_vintage`; `pipeline/lib/tic.py` looks that
month up as a column of `mfhhis01.txt` and raises `SourceUnavailable` if it is absent. TIC revises
monthly, so auto-adopting the latest release would move published figures on every re-run with
nobody deciding to — the December 2025 release moves Japan and the UK past their prose tolerances.
Moving the pin is an editorial act.

`_meta.tic_grand_total_b` is TIC's all-country total for that month. It is a **cross-check, never a
published figure**: it and Debt to the Penny's publicly-held balance are different dates, so their
quotient is not a well-defined share. `check_snapshots` uses it to corroborate the curated 30%
within 3 percentage points and nothing renders it.

## The freshness gap, `curatedVintage()` and `mixedVintage()`

`vintageOf(meta)` (`src/data/index.ts`) returns `null` for a curated snapshot: it has neither
`provenance.vintage` nor `provenance.retrieved_at`, because nothing was fetched. Passing a curated
dataset's `_meta` to `vintageOf` silently ships a figure with **no freshness stamp at all** — the
gap named as edge case 1 in issue #6.

Use `curatedVintage(meta, asOf)` instead, passing the dataset's own as-of date (e.g.
`debtMaturity.data.avg_maturity_as_of`):

```ts
curatedVintage(meta, '2026-08-07')
// "Curated snapshot, as of 7 August 2026. Refreshed by hand, not auto-fetched."
```

`asOf` must be a full `YYYY-MM-DD` date: the string it composes names a day, so a month-only value
renders a day component that is not there.

It throws if called on a dataset whose `_meta.refresh.mode` is not `"curated"` — a guard against
copy-pasting it onto a fetched dataset, where `vintageOf` is correct.

For `debt_holders`, use `mixedVintage(meta, asOf)`, which names **both** dates:

```ts
mixedVintage(debtHolders._meta, debtHolders.data.as_of)
// "Treasury International Capital, November 2025 release. Debt to the Penny as of 7 August 2026."
```

It throws when `_meta.refresh.mode` is not `"mixed"` and when `provenance.vintage` is missing. That
throw is not a lint: it runs during `npm run build`, so an output that stopped being honestly
described cannot ship while the site still builds. It is also why `refresh.mode` changing from
`"curated"` to `"mixed"` had to move five consumers in one commit — the schema `const`, the
`Meta.refresh` union, this call site, the test asserting the mode, and this document.

Both are called from `src/data/figures.ts`, never from a page: since #49 the figure manifest is the
one place a figure's provenance is composed, and `/contents` reads the same entry the route does.

## `deliberate_omissions`

`debt_holders._meta.deliberate_omissions` names data that was deliberately left out, keyed by the
`discrepancies.yaml` resolution that omitted it (currently `federal_reserve_holdings`). This is
metadata for anyone reading the JSON, not something a component renders — the omission itself must
also never resurface silently if a future fetcher starts supplying the figure (`validate.py`'s
`check_snapshots` fails the build if the string `"federal reserve"` appears anywhere in
`debt_holders.data`).

The fetch #54 introduced does not open a door to it. `mfhhis01.txt` carries no Federal Reserve row,
`lib/tic.py` returns three named countries and the grand total and nothing else, and
`check_snapshots` asserts `top_foreign` is exactly `{Japan, United Kingdom, China}`. The
`"federal reserve"` blob check is untouched and still bites.

## The denominator rule (`share_of_public_pct` vs `share_of_gross_pct`)

`debt_holders.data.public_split` uses the field name `share_of_public_pct`, deliberately not
`share_pct` — the denominator is part of the field name so a renderer cannot flatten it to a bare
percentage. The complementary gross-debt figure lives at
`foreign_share_history[-1].share_of_gross_pct` (30% of publicly held debt, 24% of gross debt as of
2025) and must **never** be recomputed; both figures come from
`discrepancies.yaml -> foreign_share_of_debt`, which is the only place they are allowed to be
picked. A consumer presenting either share must name its denominator in the same string — one
formatter, reused by the chart, the `aria-label`, the live-region readout and the table.

Since #54 the relationship between the two is also **machine-checked**, because neither is derived
from the other and nothing else would notice them drifting apart: `check_snapshots` asserts
`share_of_public_pct × split.public.amount_t / total_debt_t` is within 1pp of
`foreign_share_history[year == 2025].share_of_gross_pct` — `30 × 32.14 / 39.88 = 24.2` against
`24`. That is the 32%-of-gross rebuttal itself, as arithmetic. An edit moving one share without
the other fails the build rather than shipping a mislabelled denominator of the site's own.

`data.top_foreign` carries its own resolution check: TIC November 2025 reads `683.9` for China,
published as `0.684`, and `discrepancies.yaml -> china_holdings.use.amount_t` (`0.683`) is now the
editorial **bound** that fetched value is checked against rather than the source of it. More than
`0.01T` apart re-opens the resolution instead of letting the pipeline overwrite it.

## The non-partition rule

`debt_maturity.data.composition` (bills, notes, bonds) does **not** sum to
`marketable_total_t`: `6.8 + 15.9 + 5.4 = 28.1` against a curated total of `28.0`. Separately,
`bills.share_pct` (`22`) disagrees with `bills.amount_t / marketable_total_t` (`24.3%`) — the
curated share and the curated amount are two independently-sourced figures that do not reconcile
to each other. The rule this dataset imposes on any renderer:

- Bar/band **geometry** comes from `amount_t`.
- A **percentage** is rendered only where the curated data supplies a `share_pct` field (bills
  only, currently) — never derived as `amount_t / marketable_total_t`.
- The composition is never presented as an exhaustive partition of the marketable total; the gap
  must be stated in the figure's `note`.

## `history_months` — present, deliberately unrendered

`debt_maturity.data.history_months` is a four-point maturity time series. `sections.md` §3 is
explicit that this section is not built as a time series — the finding is the gap between two
numbers (71 months average, 30-year maximum), not a trend. The field is kept in the data
(deleting curated data is a separate editorial act, out of scope for the issue that added this
contract) but no component may reference it; a test asserts `DebtMaturity.tsx` does not.

## `Dataset<DebtHolders>` / `Dataset<DebtMaturity>`

Both are now typed (`src/data/types.ts`), replacing the earlier
`Dataset<Record<string, unknown>>` placeholder. See the interfaces themselves for field-level
comments — the two traps above (denominator, non-partition) are documented inline at the fields
they apply to, not just here.

## Schema

All five outputs carry a schema, enforced on every build by `check_schema` in
`pipeline/lib/validate.py` — an output with no schema is a build failure, not a skip (#37):

| Output | Schema |
|---|---|
| `debt_holders.json` | `pipeline/schemas/debt_holders.schema.json` |
| `debt_maturity.json` | `pipeline/schemas/debt_maturity.schema.json` |
| `income_tax_by_group.json` | `pipeline/schemas/income_tax_by_group.schema.json` |
| `oecd.json` | `pipeline/schemas/oecd.schema.json` |
| `cbo_effective_rates.json` | `pipeline/schemas/cbo_effective_rates.schema.json` |

### The `_meta` asymmetry — `refresh`, and **no** `coverage`

The fetched outputs (`budget`, `revenue_sources`, `economy`, `debt`, `income_inequality`,
`bracket_history`, `party_splits`, and both states outputs) require `_meta.coverage`. **These five
do not have it and must not acquire it.** Their schemas require `_meta.refresh` instead, with
`mode` pinned to a constant — `"curated"` for four of them, `"mixed"` for `debt_holders` — and a
non-empty `reason`. Do not write a consumer that
reads `_meta.coverage` off a curated snapshot — it is absent by design, and
`curatedVintage()` is what answers the freshness question here.

`debt_holders` additionally requires `_meta.deliberate_omissions.federal_reserve_holdings`, so the
omission documented above cannot be dropped from the payload without failing the build.

One consequence, made explicit by #41. `check_meta_titles` requires every year range in a
`_meta.title` to be derived from a coverage window, and treats a range with no coverage behind it
as a **failure**, not a skip — `coverage: null` is unknown, not good news. Four of the curated five
carry no year range and are unaffected. `cbo_effective_rates` does carry one ("published anchor
years 1979-2022") and cannot satisfy the rule without acquiring the very `coverage` block this
section forbids, so it is the single entry in `validate.TITLE_RANGE_EXEMPT`, with that reason
written into the dict. Its anchor years stay pinned numerically by `check_cbo_effective_rates`
(1979 and 2022 both present) rather than by the title. Do not add a second entry to that dict for a
fetched output — give it a coverage block instead.

### What each schema pins

- **`debt_holders`** — `data` requires `total_debt_t`, `as_of`, `tic_as_of`, `split`,
  `public_split`, `top_foreign`, `foreign_share_history`. Every percentage field is bounded
  `0 … 100`, and the denominator distinction is carried in the key names the schema requires:
  `split[].share_pct` (of gross), `public_split[].share_of_public_pct`,
  `foreign_share_history[].share_of_gross_pct`. `split` has `minItems: 2` — the
  public/intragovernmental pair is not optional. `top_foreign` is pinned `minItems: 3,
  maxItems: 3`: it is a named three, not a top-N that could quietly grow a fourth row past the
  prose. `tic_as_of` and `_meta.provenance.vintage` both match `^[0-9]{4}-(0[1-9]|1[0-2])$`, so a
  thirteenth month fails the build, and `provenance` additionally requires `retrieved_at` and
  `_meta` requires `tic_grand_total_b` — a fetched output that stopped recording when it was
  fetched, or that dropped the cross-check, is a schema violation rather than a quiet gap.
- **`debt_maturity`** — `avg_maturity_months` is an integer `minimum: 1`;
  `composition[]` requires `k`, `label`, `maturity`, `amount_t` (`share_pct` is genuinely optional,
  present on one row only); `history_months[]` requires a `date` matching `^[0-9]{4}-[0-9]{2}$`
  and a numeric `v`, so a value arriving as a string fails the build.
- **`income_tax_by_group`** — `tax_year` integer; `groups` has `minItems: 6` and each group
  requires `g` and `tax_share_pct`. `income_share_pct` and `avg_rate_pct` are **optional**: an
  unpublished cell is an absent key, never a zero, which is the non-partition rule above expressed
  in the schema. Both history arrays require an integer `year` and a numeric `v`.
- **`oecd`** — `data` requires `year`, `us_pct_gdp`, `oecd_average_pct_gdp`, `us_rank`,
  `of_countries`, `countries`, `us_history`. `us_rank` is an integer `minimum: 1` and is
  deliberately **not** bounded above by a hard-coded country count. `countries` has `minItems: 10`,
  each entry requiring `c` and `v`.
- **`cbo_effective_rates`** — `data` requires `as_of`, `basis`, `not_an_annual_series`, `groups`,
  `rows`. `groups` has `minItems: 6`; each row requires an integer `year`, a `source_table` string
  and a `v` object whose **six group keys are all required numbers**. That is the constraint that
  catches a dropped quintile, which would otherwise render as a gap in the chart.

Shape and range only. The cross-field rules — the non-partition check, the denominator check, the
anchor-years-not-a-series check — stay in `validate.py`'s `check_snapshots`,
`check_cbo_effective_rates` and the pytest suite.
